The control plane's Raft and bootstrap listeners, and the Raft peer client, re-read their certificate, key and CA every 30 s, so short-lived certificates renew without a restart. A rotated certificate on any listener must be valid now, and on the control plane must keep every name the old one had; a Raft one must also verify against the cluster CA, name the same member and not be revoked. One that fails is refused and the current one kept, as is a Raft CA bundle that no longer verifies the member's own certificate. The API listener's client CA reloads too. A Raft peer connection now closes at its client certificate's `notAfter`. New `FELIX_RAFT_TLS_REVOKED_FILE` holds revoked member fingerprints and is re-read with the certificates.
