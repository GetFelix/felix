Under `joint_fence`, a leader that learned its shard from a control-plane snapshot no longer waits forever when it cannot know the replica set its generation replaced. That happened to a leader restarted after the finalize at a generation that started before it, and to a new shard whose first assignment reached its leader in a snapshot. When its log keeps no set or that generation's own, the leader now reports the generation refused with no node named, and placement names it again one generation up on the same set (step `set_unknown`), where the set being left is known. A log keeping an older set still waits, since a rename would skip a generation's set. Under Raft, finalizing `joint_fence` now needs metadata level 25, where the refusal report is kept (#1872).
