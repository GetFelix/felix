A copy whose control-plane set names another storage id for it votes in no set until a set naming its current id is learned and it has caught up, and takes records only from the leader the control plane confirms (#1009, #1331). New shards and copies from before sets vote as before. Dormant behind the `joint_fence` fleet feature, which no fleet can finalize yet. Every placement write now names each member's registered storage id (`member_storage_ids`, metadata level 22, Postgres migration 0039), so a wiped copy learns it from a move or a creation, not only from a failover. A wiped copy that is a learner refuses to open as leader and keeps its mark.
