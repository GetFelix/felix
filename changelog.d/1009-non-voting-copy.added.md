A copy whose control-plane set names another storage id for it votes in no set until a set naming its current id is learned and it has caught up, and takes records only from the leader the control plane confirms (#1009, #1331). New shards and copies from before sets vote as before. Dormant behind the `joint_fence` fleet feature, which no fleet can finalize yet. Every placement write now names each member's registered storage id (`member_storage_ids`, metadata level 22, Postgres migration 0039), so a wiped copy learns it from a move or a creation, not only from a failover. A wiped copy that is a learner refuses to open as leader and keeps its mark, which the `replica-set` file now records apart from a staged learner's (flag bit 2). Its group logs answer no fence until they hold a record of the re-admitting generation. Brokers also keep the rule off until the control plane can re-admit learners (#1737), whatever an earlier finalize of `joint_fence` says.
