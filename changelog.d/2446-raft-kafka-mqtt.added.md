A stream shard that runs on Raft (`FELIX_SHARD_ENGINE=raft`) now takes Kafka produce and MQTT publish, with the same answers and errors as the default engine. An idempotent Kafka producer's records are written one per batch at their own sequence, as the default engine stores them, so a re-send lands once across a leader change. A broker that runs Raft shards sends each MQTT message as its own batch. Before, both were refused (`INVALID_REQUEST` for Kafka, `PUBACK` 0x83 `raft_stream` for MQTT), and the `raft_stream` refusal reason is gone (#2446).
