- A Raft log on a `periodic` or `none` broker whose run rotates its storage id after a crash can count an entry once it is written: the copy's `raft-reserved` is raised and synced first, and `flushed` still waits for the fsync. A snapshot syncs such a log before it is stored, a failed periodic flush poisons the log, and every Raft log open fails on a damaged `raft-reserved`. Off until the new `raft_written_commit` fleet feature, which no build reports yet.
