The command a failing simulator seed prints, `FELIX_SIM_SEED=<n> task sim:replay`, now replays the seed exactly. It used to be a plain `cargo test`, which leaves tokio's `select!` unseeded, so two replays of one seed could finish operations at the same virtual instant in a different order. A replay built without `--cfg tokio_unstable` now refuses `FELIX_SIM_HISTORY`, and `task sim:determinism` also replays seed 1 in two processes through `task sim:replay` and fails if the histories differ (#419).
