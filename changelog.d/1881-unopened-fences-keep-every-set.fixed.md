Under `joint_fence`, a replica now keeps every replica set since the last generation it knows opened, and a failover fences all of them (#1881). Before, a replica kept one set being left, so two fences in a row that never opened (lease churn is enough, no set change needed) overwrote the older set, and a later failover could open without a write only that set held. A kept set is dropped only once the log holds a record of a newer generation. Fences carry the older sets in a new kind, `ElectionKeptFence`, sent only to peers offering the `KEPT_SETS` capability, and the `replica-set` file gains an optional section an older build refuses. No release can finalize `joint_fence` yet.
