# felix-capi

A C ABI over the Felix Rust client, and the base the Go and C# SDKs will bind
to. Like the Python and Node bindings it wraps `felix-client`, so
reconnection, redirect-following and error classification are the Rust
client's.

It builds `libfelix` as a shared library (`.so`, `.dylib`, `.dll`) and a
static one (`.a`), with the header in [`include/felix.h`](include/felix.h).

```bash
cargo build --release -p felix-capi
cc app.c -I crates/sdk/felix-capi/include target/release/libfelix.a <native libs>
```

`cargo rustc -p felix-capi --crate-type staticlib -- --print native-static-libs`
prints the system libraries a static link needs on your platform.

## The API

```c
FelixClient *client = NULL;
if (felix_client_connect("127.0.0.1:5000", "t1", token, NULL, "ca.pem", &client) != FELIX_STATUS_OK) {
    fprintf(stderr, "%s\n", felix_last_error_message());
    return 1;
}

FelixSubscription *sub = NULL;
felix_client_subscribe(client, "t1", "default", "events", FELIX_START_LATEST, 0, &sub);

uint64_t offset;
bool has_offset;
felix_client_publish(client, "t1", "default", "events",
                     (const uint8_t *)"hello", 5, FELIX_ACK_PER_MESSAGE, &offset, &has_offset);

FelixEvent *event = NULL;
if (felix_subscription_next_event(sub, 5000, &event) == FELIX_STATUS_OK) {
    const uint8_t *data;
    size_t len;
    felix_event_payload(event, &data, &len);
    felix_event_free(event);
}

felix_subscription_free(sub);
felix_client_free(client);
```

The rules are the same for every function:

- Handles (`FelixClient`, `FelixSubscription`, `FelixEvent`) are opaque.
  Everything the library hands out has a `*_free` function, which accepts
  null.
- Every fallible function returns a `FelixStatus`. `FELIX_STATUS_OK` is zero.
  The error classes match the other SDKs: `FELIX_STATUS_CONNECTION` and
  `FELIX_STATUS_SHARD_UNAVAILABLE` are worth retrying, `FELIX_STATUS_AUTH`
  is not, and `FELIX_STATUS_OUTCOME_UNKNOWN` means a write may have landed.
- `felix_last_error_message()` describes the last failure on the calling
  thread. The string is valid until the next Felix call on that thread.
- A panic inside the library is caught and returned as `FELIX_STATUS_PANIC`.
- Each client owns a small Tokio runtime, so the caller needs no async
  runtime. Calls block the calling thread. A client may be shared between
  threads; poll a subscription from one thread at a time.
- `felix_subscription_next_event` takes a timeout in milliseconds (negative
  waits indefinitely) and returns `FELIX_STATUS_TIMEOUT` when it passes,
  or `FELIX_STATUS_CLOSED` once the broker ends the stream.

This first cut covers connect, publish and subscribe on shard 0 of a stream.
Keyed publish, groups, caches and multi-shard subscribe come later.

## The header

`include/felix.h` is generated by cbindgen and checked in. After changing an
exported function, run `task capi:header` and commit the result; the `header`
test fails while the two differ.

## Tests

`task capi:test` compiles [`tests/c/pubsub.c`](tests/c/pubsub.c) against the
header, links it against both the shared and the static library, and runs the
checks that need no broker. `task capi:test -- fixture` also runs the publish
and subscribe scenarios against `felix-cluster client-fixture`, which CI does
on every pull request.
